01Study design

The bar was set before the data was seen.

A snapshot comparison of franchise-dealer used inventory, framed as September 2020 versus September 2026.

Why "September 2020 vs. current," not "pre-COVID vs. post-COVID." Supply-chain disruption was already underway by September 2020. Calling it a clean baseline would overstate what the data can show.

Three metrics, tested separately. Age, mileage, and inflation-adjusted price each get their own test. A blended quality score would hide a result where one metric moves and the others do not.

Weighted, not flat, pooling. The 2020 data reflects natural listing volume. The 2026 pull was sampled evenly across zips. Pooling both flat would mix a real market shift with a sampling artifact, so each zip's 2020 listing share is used as a fixed weight in both periods.

Two sources. A Kaggle CarGurus crawl (about 3 million national listings, September 9 to 17, 2020) and an auto.dev API pull across the study zips (September 10, 2026).

Setting practical-significance thresholds first removes the temptation to decide what counts as "meaningful" after seeing the numbers.

03SQL analysis in DuckDB

One weighted average. Audited twice.

Q6: has the weighted average real price risen by $2,000 or more? Age and mileage use the same structure.

-- Q6: weighted average real price, Sept 2020 vs Sept 2026
-- 2020 prices converted to August 2026 dollars (CPI-U)

WITH cpi AS (
    SELECT 259.918 AS aug20
         , 334.980 AS aug26
         , aug26 / aug20 AS ratio
)
, adj_weights AS (
    SELECT dealer_zip
         , cars_in_zip / (SELECT SUM(cars_in_zip)
                          FROM zip_weights
                          WHERE dealer_zip <> '30062') AS weight
    FROM zip_weights
    WHERE dealer_zip <> '30062'
)
, zip_prices_2026 AS (
    SELECT final_zip
         , AVG(price) AS av_prices_26
    FROM final_matched
    WHERE price >= 1000
    GROUP BY final_zip
)
, zip_prices_2020 AS (
    SELECT f.dealer_zip
         , AVG(c.ratio * f.price) AS cpi_adj_2020_price
    FROM cars_2020_fltrd f
    CROSS JOIN cpi c
    WHERE f.dealer_zip <> '30062'
      AND f.price >= 1000
    GROUP BY f.dealer_zip
)
SELECT ROUND(SUM(a.weight * z20.cpi_adj_2020_price), 0) AS prices_20
     , ROUND(SUM(a.weight * z26.av_prices_26), 0)       AS prices_26
     , ROUND(SUM(a.weight * z26.av_prices_26)
           - SUM(a.weight * z20.cpi_adj_2020_price), 0) AS price_variation
     , COUNT(*) AS zips  -- expect 14
FROM adj_weights a
JOIN zip_prices_2020 z20 ON a.dealer_zip = z20.dealer_zip
JOIN zip_prices_2026 z26 ON a.dealer_zip = z26.final_zip;

Caught: a one-sided filter

An early same-dealer run restricted only the 2026 side and reported prices falling $2,488. The 2020 dealers missing from 2026 averaged about $5,000 more, so the comparison was lopsided.

Restricting both periods to continuing dealers reversed the result to +$2,467.

04Python analysis

Putting a range on every estimate.

The price estimate beat $2,000 by about $500. A dealer-level cluster bootstrap measured whether that margin holds.

def cluster_bootstrap(df, weights, col, n_reps=N_REPS, seed=SEED):
    """Resample dealers within each period-zip group and return
    n_reps recomputed weighted differences."""
    rng = np.random.default_rng(seed)

    # split each period-zip group into one DataFrame per dealer,
    # once, before resampling
    groups = {}
    for key, g in df.groupby(["period", "zip"]):
        groups[key] = [d for _, d in g.groupby("dealer")]

    results = []
    for _ in range(n_reps):
        pieces = []
        for dealer_frames in groups.values():
            n = len(dealer_frames)
            picks = rng.integers(0, n, size=n)   # with replacement
            pieces.extend(dealer_frames[i] for i in picks)
        sample = pd.concat(pieces, ignore_index=True)
        results.append(weighted_diff(sample, weights, col))

    return np.array(results)

Why resample dealers, not cars

Listings from one dealer share its pricing and stocking policy. Treating them as independent would count one store's decisions dozens of times and make the intervals too narrow.

Verified before trusted

The Python point estimates reproduced the SQL results exactly before any interval was computed. All data rules stay in SQL. Python only resamples.

06Findings

Real shifts. Not meaningful ones.

Each verdict is judged against the threshold set before the data was seen, not against zero.

Q4

Vehicle age rose 5.3 months

Threshold: 18 months

Average age went from 2.66 to 3.10 years. The full interval sits above zero and below the threshold, so the increase is real but small.

Not met, with high confidence.
Q5

Mileage rose 5,883 miles

Threshold: 15,000 miles

Average mileage went from 41,594 to 47,477. Even the top of the interval, 11,620 miles, falls short of the threshold.

Not met, with high confidence.
Q6

Real price rose $2,521

Threshold: $2,000 in August 2026 dollars

The point estimate clears the bar, but the interval runs from a $2,318 decline to a $12,059 increase. Each zip rests on a handful of dealers, so which stores are drawn swings the average by thousands.

Inconclusive. The data can't separate a rise from no change.
